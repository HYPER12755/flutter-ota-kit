# Configuration

`flutter_ota_kit` can be driven entirely by configuration — there are **no
hard-coded secrets** in your committed code. This page is the complete reference
for how the SDK and the CLI resolve every value, where secrets live, and the
exact environment variables per backend.

---

## Two sources of truth

| File | Owned by | Contains | Committed? |
| --- | --- | --- | --- |
| `.flutter_ota_kit/` (with `config.json`) | the **CLI** | working state for `migrate`/`deploy` (incl. service-role / management keys the CLI needs) | **No** — auto git-ignored |
| `.env` (project root) | the **app** | secrets consumed by the app at build time via `--dart-define` | **No** — auto git-ignored |
| `lib/flutter_ota_kit_setup.dart` | generated by `init` | non-secret defaults → `configureX(...)` using `String.fromEnvironment` | Yes (safe — no secrets) |

`flutter-ota init <backend>` writes **both** files automatically and adds them to
`.gitignore`. You normally only edit `.env`.

---

## Resolution order (environment wins)

Every configurable value is resolved from, in priority order:

1. **Build-time environment** — `--dart-define`, most conveniently supplied as
   `--dart-define-from-file=.env`.
2. **Project config** — `.flutter_ota_kit/config.json` (or `~/.flutter_ota_kit/config.json`
   when you used `init --global`).
3. **Built-in defaults** (e.g. `channel: production`, `bucket: bundles`,
   `appVersion: 1.0.0`).

> The environment always wins. This means you can keep non-secret defaults in the
> generated setup file / `config.json`, and inject only the secrets at build time
> from `.env` — without ever committing them.

---

## Using `.env` at build / run time

```bash
# dev
flutter run --dart-define-from-file=.env

# release APK for device / E2E
flutter build apk --release --target-platform android-x64 \
  --dart-define-from-file=.env
```

`--dart-define-from-file` turns each `KEY=VALUE` line in `.env` into a
`--dart-define=KEY=VALUE`, which the generated setup reads with
`String.fromEnvironment`. `flutter-ota build` and `flutter-ota deploy` also read
`.env` automatically through the same mechanism.

## The generated setup file

`init` writes `lib/flutter_ota_kit_setup.dart`. It is **safe to commit** because
it contains only `String.fromEnvironment(...)` reads — no secrets:

```dart
import 'dart:io' show Platform;
import 'package:flutter_ota_kit/flutter_ota_kit.dart';

Future<void> setupFlutterOta() async {
  FlutterPatcher.configureSupabase(SupabaseUpdateConfig(
    supabaseUrl: const String.fromEnvironment('SUPABASE_URL', defaultValue: ''),
    anonKey: const String.fromEnvironment('SUPABASE_ANON_KEY', defaultValue: ''),
    bucket: const String.fromEnvironment('SUPABASE_BUCKET', defaultValue: 'bundles'),
    channel: const String.fromEnvironment('CHANNEL', defaultValue: 'production'),
    platform: Platform.android,
    updateStrategy: UpdateStrategy.appVersion,
    appVersion: const String.fromEnvironment('APP_VERSION', defaultValue: '1.0.0'),
    sdkVersion: const String.fromEnvironment('SDK_VERSION', defaultValue: '1.0.0'),
  ));
  await FlutterPatcher.init(autoApplyUpdates: true);
}
```

Call it once in `main()` after `WidgetsFlutterBinding.ensureInitialized()` and
before `runApp()`:

```dart
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await setupFlutterOta();
  runApp(const MyApp());
}
```

## SDK auto-configuration from environment

You don't strictly need the generated file. `FlutterPatcher.init()` calls an
internal `_autoConfigureFromEnv()` that detects a backend **when none was
explicitly configured**. It reads the same variables the setup file uses, so this
also works:

```dart
Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await FlutterPatcher.init(autoApplyUpdates: true); // detects SUPABASE_URL etc.
  runApp(const MyApp());
}
```

The generated setup is the recommended path because it makes the backend
explicit and keeps `autoApplyUpdates` on by default.

| Variable | Required by app | Notes |

| `SUPABASE_URL` | yes | `https://<ref>.supabase.co` |

| `SUPABASE_BUCKET` | no | default `bundles` |
| `SUPABASE_BASE_PATH` | no | prefix inside the bucket |
| `CHANNEL` | no | default `production` |
| `APP_VERSION` | no | default `1.0.0` |
| `SDK_VERSION` | no | default `1.0.0` |

## Secrets policy (summary)

- **App secrets** (anon key, DB password, R2/AWS keys, tokens) live **only in
  `.env`** and are never committed (`.env` is git-ignored).
- **CLI secrets** (service-role key, management key) are kept in the git-ignored
  `.flutter_ota_kit/config.json`; `migrate`/`deploy` also accept them as env vars
  (`SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_MANAGEMENT_KEY`, `DATABASE_URL`, …).
- The generated `lib/flutter_ota_kit_setup.dart` and `config.json` non-secret
  fields are safe to commit.
